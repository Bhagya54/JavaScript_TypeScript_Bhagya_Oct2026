# show-me-to-html

The user wants their answer saved as a standalone HTML file in the current
folder rather than read off the screen. They start such requests with **"show
me"** or **"give me"**. Treat that phrasing as the trigger even if they never
say "HTML", "file", or "save" â€” that is the whole point of the skill.

## What to do

1. **Work out the answer** to the request as you normally would (the list, the
   code, the explanation, the table â€” whatever they asked for).
2. **Render it as a self-contained HTML document** using the template below.
   Inline all styling; no external CSS/JS so the file opens anywhere by
   double-click.
3. **Name the file from a content hash** so each answer gets a unique,
   non-colliding name and identical answers reuse the same name. Compute a
   SHA-256 of the rendered HTML and take the first 12 hex characters:
   `<hash>.html` (e.g. `a3f9c1e80b27.html`). Write it to the **current working
   directory**.
4. **Reply in chat with only the file path** â€” one short line, e.g.
   `Wrote a3f9c1e80b27.html`. Do not paste the answer body into chat; the file
   is the deliverable. A one-sentence summary of what's inside is fine.

## Why content-hash names

Unique names mean a new "show me" never silently clobbers an earlier one, so the
user builds up a folder of captured answers. Hashing the content (not a random
value or timestamp) means asking the same thing twice lands on the same file
instead of piling up duplicates â€” cheap idempotency for free.

## HTML template

Keep it clean and readable. Put the user's request in `<title>` and an `<h1>`,
the answer in the body. Adapt the body to the content type â€” use `<pre><code>`
for code, `<table>` for tabular data, `<ul>/<ol>` for lists.

```html
<!DOCTYPE html>
<html lang="en">
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<title>{request}</title>
<style>
  body { font: 16px/1.6 system-ui, -apple-system, Segoe UI, sans-serif;
         max-width: 820px; margin: 2rem auto; padding: 0 1rem; color: #1a1a1a; }
  h1 { font-size: 1.4rem; border-bottom: 2px solid #eee; padding-bottom: .4rem; }
  pre { background: #f6f8fa; padding: 1rem; border-radius: 6px; overflow-x: auto; }
  code { font-family: ui-monospace, SFMono-Regular, Menlo, monospace; }
  table { border-collapse: collapse; width: 100%; }
  th, td { border: 1px solid #ddd; padding: .5rem .75rem; text-align: left; }
  th { background: #f6f8fa; }
</style>
</head>
<body>
<h1>{request}</h1>
{answer}
</body>
</html>
```

## Generating the file

Easiest reliable path: write the HTML, then hash it and rename. In one shell
step (PowerShell example) you can hash a temp file and move it:

```powershell
$tmp = New-TemporaryFile
# ... write HTML into $tmp ...
$hash = (Get-FileHash $tmp -Algorithm SHA256).Hash.Substring(0,12).ToLower()
Move-Item $tmp "$hash.html" -Force
```

Or just compute the SHA-256 of the HTML string yourself and use the Write tool
to create `<hash>.html` directly â€” either is fine. The only hard requirements:
unique hash-based name, `.html` extension, current folder, and a one-line chat
reply with the path.
